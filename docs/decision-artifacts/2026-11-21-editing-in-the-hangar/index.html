Editing a person without leaving the Hangar

You said changing a character felt clunky, opaque and mysterious. You were right. Here is what goes wrong today, every change a PM makes to a person, a working mockup of the fix, and six choices for you to settle. Your answers save as you pick them.

What goes wrong today

!

Edit throws you out. "Edit" starts a draft and then opens a new chat in flying mode with a prefilled prompt. You lose the page you were on, and nothing says how to get back.

!

Nothing on the page is editable. The brief (the character's system message) and every field can only be changed by asking Aviator, even a one-word fix to a role.

?

Skills go nowhere. A person file can carry a skills: line, but I checked: today nothing reads it. The background session that plays them is never told about those skills. So the link was hard to find because there was nothing behind it.

?

Where they appear is read-only. The page lists the workflows and starters that use someone, but you can't add or remove them there.

The changes you'd want to make, and how each one would work

Most changes are typing or picking, so they happen right on the page. Aviator is for the changes where words need writing, and trying someone out is a chat by nature.

Six choices for you

Each one has my recommendation and a "Something else" option. Add a note anywhere. I'll build on the recommended options while you look, and change course on anything you pick differently.

What this changes beyond people

The same pattern carries into the workflow and scenario builders I'm building next: the page is the editor, changes save to a draft as you go, Aviator sits in a pop-over for the writing, and Publish stays the one gate. A scenario's cast, title and invented data are typed or picked on the page. Its script gets Aviator's help, and "Try it" plays it in the player.
