Library Design Round
Flight Deck · Library design round · 21 Nov 2026

The Library: where every piece of work and every demo starts

You want to keep the Library and use it to start two things: real work, such as a PRD review, and demos of scenarios. Each entry should describe itself from its own metadata. Today's contents are temporary. This page shows what's settled, a working mockup, where each card's words come from, and five choices. Your picks save as you make them.

The short version
  • Top half: a hero card for each featured product skill, such as Intent shaping, so you start real work from the Library. Skills that aren't featured sit in a slim row underneath.
  • Bottom half: scenarios and demos, including the ones you've already flown.
  • The Library stops being a folder of hand-written prompts. It's built from what's published in the Hangar. A skill is featured by one line in its workflow.json.
  • Every word on a card comes from the thing itself: workflow.json or scenario.json. Publish a scenario in the Hangar and its card appears. There is nothing else to keep in sync.
  • Today's 13 canned sessions and 6 templates are retired. Seven become generated Start cards. The other six were free-standing prompts with no workflow behind them, and they go.

4 · Where every word on a card comes from

Card anatomy

Each numbered part of the demo card reads one field of the scenario's own file. Fields marked new don't exist yet. The scenario builder would ask for them.

// workspace/scenarios/decision-review/scenario.json { "scenario": "decision-review", 2"title": "Steering prep", 3"summary": "Seven decisions stand between …", 4"workflows": ["decision-review"], ← today "workflow" 5"participants": ["risk-review", …], new 7"length_minutes": 4, new 8"opens_in": "chat", or "inbox" new "opening": "Before we take this …", new "library": { "featured": true, "order": 1 }, "script": "script.md" } // 1 and 6 are worked out from script.md: // count the canned turns and the live ones. // All canned = "Scripted", all live = "Live", // a mix = "Mixed".

A work card reads workflow.json the same way: title, summary, and its inputs, which become the short form you fill in before Start. Nothing on either card is typed into the Library itself.

5 · Writing that the cards need

Today's titles describe the plumbing, not the story

Generated cards are only as good as the metadata. Today's scenario summaries read "The Decision review workflow played with invented open decisions on the Allowances launch." That tells a builder what it is, but it won't make anyone want to watch. The scenario builder should ask for a title that names the situation and a summary that states the tension, in at most 25 words. I'll rewrite the seven existing ones when this is built.
